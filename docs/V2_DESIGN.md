# Mah v2 design

Status: **proposal, not implemented.** Nothing in this document has been
built yet. Read `docs/ARCHITECTURE.md`, `docs/RUNTIME.md`, and
`.claude/skills/compiler-construction/SKILL.md` first — this document
assumes that context and doesn't re-explain why v1 can't support recursion,
closures, or composite data. For match guards, arrays/lists, generics,
traits, the future type system, and the future async model, see
[`docs/NEXT_PHASES.md`](NEXT_PHASES.md) — all deferred past M9 below, but
the design here is kept forward-compatible with them; read it too before
implementing the resolve/codegen passes so nothing forecloses them.

## Summary of decisions this doc is built on

Confirmed with the user:

1. Activation records are **heap-allocated**, linked by a static chain
   pointer (SCP, for lexical/closure access) — not put on a native call
   stack. This is what makes JS-style *escaping, by-reference* closures
   correct (a stack-allocated static chain breaks the moment a closure
   outlives its creating call). See "Calling convention" below.
2. **Both the lexer and the parser are hand-written**, producing a real
   AST, compiled in separate passes (parse → resolve → codegen).
   `compiler-generator/`'s LL(1)-table generation is retired for Mah's own
   pipeline (it stops being regenerated by `make lang`; leave the directory
   in place as a reference/archive rather than deleting working code, but
   nothing in the new pipeline depends on it). This is what makes pattern
   matching, expression-blocks, struct declarations, and forgiving error
   recovery tractable.
3. The struct-declaration keyword is **`struct`** (not `object`).
4. There is no separate anonymous-function keyword. `fn` is the one
   function syntax, used both as a statement (`fn name(...) { ... }`,
   sugar for `let name = fn(...) { ... }`) and, with the name omitted, as
   an **expression** producing a closure value (`fn(...) { ... }`) that
   can be assigned, returned, or passed as an argument like any other
   value. See "Grammar sketch" and "AST node shapes" below.
5. Match guards (`pattern if cond => ...`) are **deferred past M4** —
   design captured in `docs/NEXT_PHASES.md` so M4's codegen shape doesn't
   have to be reworked when they land.
6. **`none`/`some(x)`** are Mah's null equivalent — a built-in, lowercase,
   reserved-keyword `Option`-shaped enum (`none`, or `some(x)` holding a
   value). Missing-return and no-tail-expression cases produce `none`. See
   "Built-in `some`/`none`" below.
7. **`defer`** runs a statement when the block it's written in exits (any
   exit: fallthrough, `return`, `break`, `continue`), most-recently-deferred
   first. Block-scoped like Zig's `defer`, not function-scoped like Go's.
   See "`defer`" below.
8. A future **type system** (types as runtime values; type-level code
   written in ordinary Mah syntax — `if`/`for`/functions — over those
   values, with TypeScript-style control-flow narrowing), and a future
   **async model** (async-by-default calls, `detach`/`.await`, a JS-style
   call-stack-plus-microtask event loop) are out of scope for all
   milestones below, but every pass in this doc is designed to leave room
   for them. See `docs/NEXT_PHASES.md`.
9. This document is the thing to review/approve before any code changes.

## Non-goals (explicitly out of scope for M0–M9, but planned later)

Not implemented in any milestone below — deferred to phases after M9, with
design notes captured now in `docs/NEXT_PHASES.md` so M0–M9 don't foreclose
them:

- A garbage collector. Design so one can be added later (roots, heap object
  shapes) but do not implement collection.
- A type system / type checking (types as runtime values, control-flow
  narrowing).
- An async model (`detach`/`.await`, call-stack + microtask event loop).
- Match guards.
- Arrays/lists.
- Generics.
- Traits/interfaces.

Also out of scope: keeping v1 program compatibility. Breaking
`examples/*.mh` syntax is expected and fine — this is a pre-1.0 MVP.

## Pipeline shape

```
source text
  │  (unchanged) preprocessor.py: import/export inlining, source map
  ▼
tokens            -- lexer (hand-written or still declarative token table)
  ▼
AST               -- hand-written recursive-descent / Pratt parser
  │                  errors become ErrorNode + diagnostic, parsing continues
  ▼
Resolved AST      -- resolve pass: scope tree, every Ident -> (decl node,
  │                  lexical depth), every struct/enum reference -> its decl,
  │                  independent of declaration order at module scope
  ▼
IR                -- codegen pass: walks resolved AST, emits instructions
  ▼
heap-frame VM     -- extended code_interpreter.py
```

Three passes, each assuming the previous succeeded. This directly replaces
today's "parsing IS codegen" single pass (`docs/ARCHITECTURE.md`).

## Grammar sketch (EBNF-ish, not the final `.lang`/parser source)

```
program        := item*
item           := fn_decl | struct_decl | enum_decl | stmt

fn_decl        := "fn" ident "(" params? ")" block   # sugar, see fn_expr
struct_decl    := "struct" ident "{" (ident ",")* "}"
enum_decl      := "enum" ident "{" enum_variant ("," enum_variant)* "}"
enum_variant   := ident | ident "{" (ident ",")* "}"

stmt           := let_stmt | assign_or_call_stmt | if_stmt | while_stmt
                | defer_stmt
                | "break" | "continue" | "return" expr? | expr

let_stmt       := "let" ident "=" expr
defer_stmt     := "defer" stmt               # see "`defer`" below
block          := "{" stmt* expr? "}"        # last bare expr = block's
                                              # value; #e (no bare tail) ->
                                              # `none`, see below

expr           := match_expr | if_expr | fn_expr | binary_expr | ...
if_expr        := "if" expr block ("elif" expr block)* ("else" block)?
match_expr     := "match" expr "{" match_arm ("," match_arm)* ","? "}"
match_arm      := pattern "=>" expr          # `pattern if cond => expr` is
                                              # future work, see NEXT_PHASES.md
fn_expr        := "fn" ident? "(" params? ")" block   # name optional

pattern        := literal_pat | ident_pat | wildcard_pat
                | struct_pat | enum_pat
wildcard_pat   := "_"
ident_pat      := ident                         # fresh binding, always matches
struct_pat     := ident "{" (ident (":" pattern)?) ("," ...)* "}"
enum_pat       := ident "." ident (struct_pat_fields)?

struct_lit     := ident "{" (ident ":" expr) ("," ...)* "}"
enum_lit       := ident "." ident (struct_lit_fields)?
field_access   := expr "." ident
field_assign   := expr "." ident "=" expr
```

Notes:

- **One function syntax, not two.** `fn` is always `"fn" ident? "("
  params? ")" block`. With a name, it's parsed as a statement/item and
  desugars to `let name = <the same node without the name>` — so a
  top-level `fn square(n) { return n ** 2 }` is just sugar for binding a
  closure value to `square`, not a structurally different thing from an
  anonymous one. Without a name, it's an ordinary expression usable
  anywhere an expression is — `let make_adder = fn(x) { return fn(y) {
  return x + y } }`, or passed straight into a call:
  `apply(fn(x) { return x * 2 }, 5)`. Internally this is one AST node,
  `FnExpr(name: Optional[str], params, body)`; the parser strips the name
  off into a wrapping `LetStmt` when present. This is required for
  closures to be assignable/returnable/passable at all — see "Calling
  convention" below for what makes a `fn` expression an actual closure
  (captures the enclosing frame) rather than just a code pointer.
- A block (`{ ... }`) is always an **expression**: zero or more statements
  followed by an optional trailing bare expression, which is the block's
  value (no trailing expression → the block's value is a unit/zero, same
  as today's implicit-zero-return). `if`/`match` reuse this: every
  branch/arm is a block, and the whole `if`/`match` is an expression whose
  value is whichever branch ran.
- Distinguishing `ident_pat` (fresh binding) from `struct_pat`/`enum_pat`
  is by what follows: a bare identifier not followed by `{` or `.<Ident>{`
  is a binding, matching Rust's own rule that lowercase bare names in
  pattern position always bind (never compare against an existing
  variable) — no special syntax needed.

## AST node shapes (representative, Python dataclasses)

```python
# Expressions
NumberLit(value: Decimal)
StringLit(value: str)
BoolLit(value: bool)
Ident(name: str)                                  # resolved -> decl ref
Unary(op: str, operand: Expr)
Binary(op: str, lhs: Expr, rhs: Expr)
Call(callee: Expr, args: list[Expr])
FieldAccess(obj: Expr, field: str)
StructLit(type_name: str, fields: dict[str, Expr])
EnumLit(type_name: str, variant: str, fields: dict[str, Expr])
Block(stmts: list[Stmt], tail: Optional[Expr])    # a block IS an expr
If(cond: Expr, then: Block, elifs: list[(Expr, Block)], else_: Optional[Block])
Match(scrutinee: Expr, arms: list[MatchArm])
FnExpr(name: Optional[str], params: list[str], body: Block)  # closure
                                     # literal; name is parse-time-only,
                                     # stripped into a wrapping LetStmt by
                                     # the parser when present (see below)

# Patterns
WildcardPat()
BindPat(name: str)
LiteralPat(value: Expr)                           # number/string/bool
StructPat(type_name: Optional[str], fields: dict[str, Pattern])
EnumPat(type_name: str, variant: str, fields: dict[str, Pattern])
MatchArm(pattern: Pattern, guard: Optional[Expr], body: Expr)

# Statements / items
LetStmt(name: str, value: Expr)
AssignStmt(target: Expr, value: Expr)              # target: Ident | FieldAccess
ExprStmt(value: Expr)
IfStmt / WhileStmt(cond: Expr, body: Block)
BreakStmt() / ContinueStmt() / ReturnStmt(value: Optional[Expr])
DeferStmt(stmt: Stmt)                              # see "`defer`" below
# no separate NoneLit/SomeExpr/SomePat/NonePat nodes: `none`/`some(x)`
# parse straight to EnumLit("Option", "none"/"some", ...) and, in pattern
# position, EnumPat("Option", "none"/"some", ...) — see "Built-in
# `some`/`none`" below
# no separate FnDecl node: `fn name(...) { ... }` parses straight to
# LetStmt(name, FnExpr(name=name, ...)) — see "Grammar sketch" above
StructDecl(name: str, fields: list[str])
EnumDecl(name: str, variants: list[EnumVariantDecl])
EnumVariantDecl(name: str, fields: Optional[list[str]])  # None = unit variant
```

`ErrorNode` (any position) carries a message + span and is valid wherever
an `Expr`/`Stmt`/pattern is expected, so parsing never aborts (see
"Forgiving errors" below).

## Calling convention: heap frames, static chain, explicit return stack

Every call allocates a **frame object on the heap**:

```python
class Frame:
    slots: list          # params, then locals, in declaration order
    static_parent: Optional[Frame]   # the frame lexically enclosing this
                                      # function's *definition* (not caller!)
```

- `static_parent` is fixed at closure-creation time: when a `fn(...) { }`
  expression is evaluated (named or anonymous — same node, see "Grammar
  sketch"), the resulting closure value is
  `Closure(code_address, defining_frame)` where `defining_frame` is
  whatever frame was current at that point. Every call to that closure
  creates a new `Frame(slots=[...], static_parent=defining_frame)`.
- The **resolve pass** turns every `Ident` reference into `(depth, slot)`:
  `depth` = how many `static_parent` hops from the *use* site's own frame
  to the frame that declared it (0 = own frame), `slot` = index within that
  frame's `slots`. This is computed once at compile time from the AST's
  lexical nesting — the VM never searches by name.
- Variable access opcode becomes `load depth, slot -> dest` /
  `store src -> depth, slot`, walking `static_parent` `depth` times from
  the **current frame** then indexing `slots[slot]`. This subsumes v1's
  `pid`/`setpid`/fixed-global-address model entirely.
- **Return control flow** doesn't need a per-frame dynamic link — nothing
  but "resume the caller" needs it, and that's exactly what a call needs to
  save/restore: a tiny explicit stack of `(return_pc, caller_frame)`,
  analogous to v1's existing `sp` return-address counter
  (`docs/RUNTIME.md`) but now also restoring *which frame is current*, not
  just *which instruction*. `call` pushes `(pc, current_frame)`, sets
  `current_frame = new Frame(...)`, jumps; `ret` pops, restores both.
- Recursion now works for free: each call gets its own `Frame` object: a
  recursive call's locals never alias its caller's, because they're
  different heap objects, not the same fixed address.
- A closure capturing an *outer* variable and later mutating it is just
  "write through `static_parent` chain to that frame's `slots[i]`" — since
  every frame is a distinct heap object referenced by pointer, this is
  automatically **by-reference**, live, shared with anything else holding
  the same frame (the JS semantics you asked for) — no separate boxing
  scheme needed, because the whole frame already is the box.

This is a direct, deliberately simple starting point (walk `static_parent`
`depth` times per non-local access). If a hot path with deep nesting ever
matters, the standard optimization is closure conversion (copy just the
captured variables into a small flat environment at closure-creation time
instead of linking whole frames) or a *display* (array of current frame per
lexical depth, O(1) lookup) — not needed for correctness, worth a comment
in code but not part of the v2 milestone.

## Heap object model

Every heap value is a small tagged Python object (a real Python object
*is* the tag, via `isinstance`/dataclass type — no manual bit-packing
needed in a Python host):

```python
class Frame: ...                 # above
class Closure:
    code_address: int
    defining_frame: Frame
class StructInstance:
    type_name: str
    fields: dict[str, Any]       # value: immediate or another heap pointer
class EnumInstance:
    type_name: str
    variant: str
    fields: dict[str, Any]       # {} for a unit variant
```

Numbers (`Decimal`), strings (`str`), and booleans (`bool`) stay as
**immediate** Python values stored directly in a slot — same as v1, just
with `bool` becoming its own real type instead of comparisons producing
`int` 0/1 (this satisfies "boolean" being a listed data type distinct from
number). They don't need heap indirection: Python's own reference-counted
object model already gives strings/Decimals reference semantics for free,
and per the language spec they're the value types the user actually wants
copied, not aliased, on assignment.

The **allocator** for heap objects (`Frame`, `Closure`, `StructInstance`,
`EnumInstance`) is a bump-style Python list append — allocate, append,
return an index or the object itself as the "pointer" (Python object
identity already gives us this almost for free; a real bytecode VM in a
lower-level host would need an explicit heap array + free-list design, but
there's no reason to simulate that in Python — just don't call anything
`free`/`drop`). **No reclamation** happens; this matches "no GC for now."

**GC readiness**, for whenever that's revisited: roots = `current_frame`
(walk its `static_parent` chain) plus the return-info stack's saved
`caller_frame`s plus any module-level globals frame. Every heap object
above already exposes its outgoing pointers via plain Python attributes
(`.static_parent`, `.defining_frame`, `.fields` values that happen to be
heap objects), so a future mark-sweep pass is a straightforward graph walk
— no redesign needed later, which was the point of doing this now instead
of ad hoc.

## Structs (`struct`) and enums

- `struct Point { x, y }` declares a **shape**: field names only (no types
  — matches "number/boolean/string/struct/enum" being the whole type
  system; a field can legally hold any of them). `Point { x: 1, y: 2 }`
  constructs a `StructInstance`. `p.x` reads, `p.x = 3` writes — both
  resolved at compile time against the struct's known field set (compile
  error on an unknown field, the one piece of "type checking" v2 needs).
- `enum Shape { Circle { r }, Square { s }, Empty }` declares variants,
  each either unit (`Empty`) or struct-shaped (`Circle { r }`).
  `Shape.Circle { r: 2 }` constructs an `EnumInstance`; `Shape.Empty`
  (no braces) constructs one with `fields={}`. Matching is by
  `(type_name, variant)` tag plus recursive field patterns — see the
  compiler-construction skill for the general technique; concretely here,
  `match` compiles to a chain of tag-check-then-branch instructions using
  the same backpatching primitives v1's `if`/`elif` already has (new piece
  is that each arm's *body* writes into a shared **result slot** instead of
  falling off the end, since `match` is an expression — see next section).

## Built-in `some`/`none`

Mah's null equivalent. Conceptually a built-in enum shaped like Rust's
`Option` (`none` = empty, `some(x)` = holds one value), reusing the exact
same `EnumInstance` representation as user `enum`s (`type_name="Option"`,
`variant="none"` or `"some"`, `fields={}` or `{"value": x}`) — no new heap
kind needed.

- **Unqualified, lowercase, by design.** User enums are accessed with
  `Type.Variant` (`Shape.Circle { r: 2 }`); `some`/`none` deliberately are
  not — you write `some(x)`/`none` directly, matching how the user
  described them and mirroring Rust's own prelude, which auto-imports
  `Option::Some`/`Option::None` into scope unqualified as `Some`/`None`.
  Mah's version is lowercase, consistent with the rest of the language's
  keyword casing (`let`, `if`, `while`, `fn`, `struct`, `enum`).
- **`some`/`none` are reserved keywords, not ordinary identifiers.**
  Rust can let `Some`/`None` be plain (if prelude-imported) names because
  its binding-vs-value pattern ambiguity is resolved by case (lowercase =
  fresh binding, capitalized = existing constructor) — Mah can't use that
  trick since `some`/`none` are lowercase. Making them reserved keywords
  instead (like `true`/`false` presumably already are) sidesteps the
  ambiguity entirely: they can never be shadowed by `let none = ...`, and
  in pattern position a bare `none`/`some(pattern)` is always the
  Option check, never a fresh binding, with no case-sensitivity trick
  required. This needs one lexer/parser carve-out (`some`/`none` reserved)
  but no change to the general `Type.Variant` enum design otherwise.
- **Pattern position:** `none` and `some(pattern)` are valid patterns
  (`match_arm` case), desugaring to `EnumPat("Option", "none", {})` /
  `EnumPat("Option", "some", {"value": pattern})` — ordinary enum patterns
  under the hood, just with implicit `type_name` and unqualified spelling.
- **`none` is a shared singleton**, not reallocated per use — it carries no
  fields, so nothing about heap-object identity semantics changes by
  reusing one instance everywhere `none` is produced (implicit returns,
  empty block tails, explicit literal `none`).
- **Where `none` shows up implicitly:**
  - A function that runs off its body without an explicit `return`
    produces `none` (replacing v1's implicit-zero-return, see
    `docs/RUNTIME.md`'s `fn_ret_inject_zero`).
  - A block whose last statement ends with `;` (no bare trailing
    expression) — including an empty block `{}` — produces `none` as its
    value. See "Blocks/if/match as expressions" below for how this plugs
    into destination-slot codegen.
- Registering the builtin `Option` type happens once, at compiler
  initialization, independent of user `enum` declarations (M3) — see that
  milestone's note below.

## `defer`

`defer <stmt>` schedules `<stmt>` to run when the block it's written in
exits — by falling off the end, or by a `return`/`break`/`continue` that
transfers control past that block's `}` — most-recently-deferred first
(LIFO): "inner defer runs first, first defer runs last." **Block-scoped**,
like Zig's `defer`, not function-scoped like Go's: a `defer` inside a
nested `{ ... }` runs when *that* block exits, not when the whole function
returns. A `return` several blocks deep therefore unwinds one block at a
time — each block's own defers run (LIFO) before control moves out to the
next enclosing block, whose defers then run (LIFO) in turn, and so on until
the unwind reaches the actual target (the function, for `return`; the
nearest enclosing loop, for `break`/`continue`).

- `defer` is a **statement**, never a block's tail expression (it's in
  `stmt`, not `expr`, in the grammar sketch above) — it produces no value.
- Only a `defer` that's *actually executed* registers — one inside an
  untaken `if`/`match` branch never fires, matching ordinary execution
  order. This means defer registration is inherently a runtime, per-call
  thing, not something fully resolvable at compile time.
- **Codegen sketch:** compile the deferred statement as a zero-argument
  closure body (reusing exactly the `Closure(code_address, defining_frame)`
  representation already designed for `fn` expressions in "Calling
  convention" above); executing `defer stmt` at runtime pushes that closure
  onto a small per-block-activation list (naturally living on the current
  `Frame`, since frames are heap objects already). Every point where the
  block can exit — the fallthrough path, and every `return`/`break`/
  `continue` whose target is outside this block — pops and calls that
  list's closures most-recent-first before actually completing the jump.
  This is additive to the calling convention, not a new mechanism: "run a
  closure with no arguments" is just an ordinary call.
- Implicit `none` returns (see above) still run defers: falling off a
  function body is exit-by-fallthrough from that function's outermost
  block like any other, so its defers fire the same as an explicit
  `return`.

## Blocks/if/match as expressions

Codegen for `Block`/`If`/`Match` takes (or allocates) a **destination
slot** for the whole construct's value, in addition to whatever slots its
substatements use:

- `Block`: compile each statement normally; if there's a trailing
  expression, compile it into the block's destination slot (a plain `=`
  copy, same instruction v1 already has); if not, load the shared `none`
  singleton into `dest` (see "Built-in `some`/`none`" above — this
  replaces v1's implicit-zero convention, generalized from "missing
  `return`" to "empty block value," covering both with one default).
- `If`/`Match` as expressions: same idea one level up — every
  branch/arm is itself compiled as a `Block` targeting the *same* shared
  destination slot, then jumps to a common join point after. This is
  additive to v1's existing `@save`/backpatch jump machinery
  (`docs/RUNTIME.md`), not a replacement — the new part is only "thread a
  destination address through," not new control-flow primitives.
- `if`/`match` used as plain statements (value discarded) just target a
  scratch temp and ignore it — no special-casing needed.

## Forgiving errors (parser-level recovery)

The hand-written parser, on an unexpected token where a construct is
expected:

1. Emits a diagnostic (`message`, span) into a side list (not an exception).
2. Inserts an `ErrorNode` in the tree at that position, so every consumer
   (resolve pass, codegen, LSP) has *something* structurally valid to walk
   past instead of a hole.
3. **Synchronizes**: discards tokens until a recovery point — a statement-
   starting keyword (`let`, `if`, `while`, `fn`, `return`, `struct`,
   `enum`, `match`, ...), a `;`, or a `}` closing the current block — then
   resumes normal parsing.

Resolve/codegen passes skip over `ErrorNode`s (don't try to resolve or
generate code for them; if one appears where a value is needed, substitute
`none` so codegen doesn't need to special-case "missing" everywhere — the
same default used for a missing return or an empty block, see above).
`mah.py build`/`run` still refuses to execute a program with
any parse or resolve errors — forgiving *parsing* is for the LSP's benefit
(keep giving hover/completion/most diagnostics across the rest of a file
that has one syntax mistake), not a license to run broken programs.

## LSP rename (and why it should stop being a third scope model)

`lsp/analysis.py` today re-derives its own scope tree from raw tokens
(`_build_scopes`), independent of the real compiler — a second
implementation of scoping that can drift from the first (see
`docs/ARCHITECTURE.md`'s Tooling section). v2 should **retire that** in
favor of the LSP running the real resolve pass and reading its symbol
table directly: a decl node with a list of every `Ident`/pattern-binding
node that resolved to it. Then:

- `textDocument/rename`: find the decl for the symbol under the cursor,
  collect every reference node bound to it (already computed by resolve),
  emit one `TextEdit` per occurrence as a `WorkspaceEdit`.
- Cross-file: an exported symbol's rename must also account for the
  preprocessor's mangling (`__mah_m{idx}_{name}`,
  `docs/ARCHITECTURE.md`) — rename the *source* name at the declaration and
  at every import-site reference, not the mangled combined-text form the
  compiler actually sees. This needs the preprocessor's existing segment
  source-map, unchanged.
- Same real symbol table gets go-to-definition, hover, and completion "for
  free," fixing today's duplicate-scope-logic maintenance cost as a side
  effect, not an extra task.

   `fn`/`return`, `print`/`input`/`sin`/`cos`, imports unchanged). Resolve +

   New: `compiler/ast_nodes.py`, `compiler/resolve.py`, `compiler/codegen.py`;
   rewrote `compiler/lexer.py`, `compiler/parser.py` by hand. Removed:
   `actions.py`, `compiler/ir_generator.py`. `mah.lang`/`compiler-generator/`
   left in place but archived — `make lang` is now a no-op (see Makefile).

   dest)` (pure internal convention, not user-visible).
   **Known regression, expected per this plan:** `lsp/` now fails to import
   (`actions.py`/`compiler.ir_generator` gone) — LSP functionality is
   unavailable until M6–M8 rework it, as flagged when this doc was written.
2. **M1 — heap frames + calling convention. ✅ Landed.** Replaced M0's
   single flat shared-array/fixed-address model with heap-allocated
   `Frame`s (`slots` + `static_parent`) linked into a static chain, plus
   a first-class `Closure` value (`code_address`, `defining_frame`,
   `slot_count`, `param_count`, `name`) -- see `runtime_values.py`. Every
   IR operand is now a `(depth, slot)` pair instead of a bare address;
   `resolve.py` assigns slots per *frame level* (one per `fn` nesting,
   not per lexical block) and computes each reference's static-chain
   `depth`; `codegen.py` continues allocating temporaries from the same
   `FrameLevel` objects the resolver used. Calls push
   `(return_pc, caller_frame)` onto an explicit return stack and switch
   to a brand-new `Frame` per call (never reused/aliased, which is what
   makes recursion safe); `ret` copies into an interpreter-local return
   register and a new `retval` opcode copies it into the caller's
   destination slot once the caller's frame is current again. `fn` is no
   longer its own statement: it is one AST node, `FnExpr` (optional
   name), usable as an expression anywhere; `fn foo(...) { ... }` at
   statement level is now parsed as sugar for
   `let foo = fn(...) { ... }`. `Call.callee` is a full expression (in
   practice always an `Ident`) instead of a bare name string, so a call
   resolves its callee like any other identifier reference -- this is
   what lets a closure stored in a variable be called.
   Verified against all of `examples/*.mh` (unchanged output) plus:
   recursion (`fact(5)` → `120`); closures capturing an outer variable by
   reference, with two calls to the same outer function producing two
   independent captured frames (`make_counter`/`c1`/`c2` → `1`, `2`, `1`,
   `3`); an anonymous `fn(...)` expression assigned to a variable and
   called (`add(2, 3)` → `5`); a function falling off its end implicitly
   returning `none` (prints as the string `"none"`); a runtime arity
   mismatch raising a clean `Argument Count is invalid` error instead of
   a Python traceback; `mah.py build`'s IR dump still working structurally
   (addresses just print as `(depth, slot)` tuples now); and the M0
   operator-precedence/associativity checks (`-2**2` → `-4`,
   `2**3**2` → `512`, etc.) still holding.
   New: `runtime_values.py` (`Frame`, `Closure`, the `NONE_VALUE`
   singleton). Rewrote: `compiler/resolve.py` (frame-level-aware,
   `FunctionInfo`/`FIRST_ADDRESS` removed), `compiler/codegen.py`
   (`(depth, slot)` addressing, `closure`/`call`/`ret`/`retval` opcodes,
   `FIRST_TEMP`/per-function `return_address` bookkeeping removed),
   `code_interpreter.py` (`Frame`-based `run_code`, flat `stack`/`sp`
   model removed). Updated `compiler/ast_nodes.py` (`FnDeclStmt` removed
   in favor of `FnExpr`; `Ident.address`/`AssignStmt.target_address` are
   now `(depth, slot)` tuples; `Call.info` removed) and
   `compiler/parser.py` (one `_parse_fn_expr()` used from both statement
   and expression position). `mah.py`'s `generate_code` now passes
   `resolver.global_frame` into `Codegen`, and `run_code` takes the
   compiled `global_slot_count` to size the initial frame. `Makefile`'s
   `install-cli`/`install-lsp` now also copy `runtime_values.py`.
   Deliberate design choices worth flagging: arity is now checked at
   **runtime** inside the `call` opcode rather than at resolve time,
   since a call's callee is not always statically known to be a specific
   function any more (it can be a closure value passed around or
   returned from elsewhere) -- consequently an arity-mismatch error names
   the function only when the closure happens to have a `name` (an
   anonymous closure's error just says "function"). M0's deliberate
   "prevent self-reference" trick (`FunctionInfo`'s early-duplicate-check
   / late-scope-insert timing, so a function could never see its own
   name) is gone and *replaced by* the opposite, deliberately-enabled
   behavior: a named `let`/`fn` binding whose value is a `FnExpr` is
   declared in its own frame level *before* its body is resolved, so it
   can call itself -- recursion is the entire point of M1. One thing not
   spelled out by the M1 design doc that the implementation had to
   decide: `none` (the `_NoneValue` singleton) is falsy (`__bool__`
   returns `False`) -- without this, existing examples like
   `new_prime_numbers.mh`, which use a bare `return;` (now `none` instead
   of M0's `Decimal(0)`) as a falsy early-exit inside an `if` condition,
   would regress (every number would test "truthy"/prime). Making `none`
   falsy was the minimal fix and is a natural reading of "no value" even
   ahead of the full `Option`/`some`/`none` enum landing in M3.
3. **M2 — structs (`struct`). ✅ Landed.** `struct Name { field, ... }`
   declares a fixed field shape (names only, no types); `Name { field: expr,
   ... }` constructs a heap-allocated `StructInstance` (`runtime_values.py`)
   -- a struct is just another heap object, so Mah variables holding one are
   references, never copies, exactly like M1's `Frame`/`Closure`. `p.x`
   reads a field, `p.x = v` writes it (mutating the same heap object --
   visible through any alias); both are chainable (`a.b.c`, `o.inner.v =
   99`) via a single `FieldAccess` AST node applied uniformly as a postfix
   to every primary expression, so it binds tighter than unary `-` and `**`
   (`-p.x` is `-(p.x)`, `p.x ** 2` is `(p.x) ** 2`).
   **The if/while struct-literal ambiguity** (same one Rust and Go hit):
   since `if EXPR { ... }` and `while EXPR { ... }` both have `EXPR`
   immediately followed by a required `{`, a bare struct literal directly
   in that condition position is genuinely ambiguous with the
   if/while-body block (`if x { ... }` -- is `{` starting a struct literal
   on `x`, or the body?). Solved the same way Rust/Go solve it: a bare
   struct literal is syntactically disallowed directly in an `if`/`while`
   (and `elif`) condition -- parenthesizing re-enables it. Implemented as a
   parser instance flag, `self._struct_literal_allowed`, consulted only at
   the one decision point (seeing `ID` then `{` in `_parse_primary`) and
   temporarily forced back to `True` inside `(...)` grouping and each
   call/paren-arg expression, where the ambiguity can't occur (a matching
   `)`/`,` unambiguously ends the expression) -- a purely syntactic,
   parse-time restriction, not a semantic one; `if x { print("hi") }`
   always parses `x` as a plain identifier regardless of what it holds at
   runtime.
   **Compile-time literal validation vs. runtime access validation**
   (a deliberate split, not an oversight): a struct *literal* always names
   its struct type explicitly right there in the syntax, so
   `compiler/resolve.py` fully validates it statically -- undeclared struct
   type, duplicate field in the literal, duplicate field in the
   declaration itself, and an exact match between provided and declared
   field names (any missing and/or unknown field is a compile-time error
   naming the specific field(s)) -- all raised during `resolve_expr`/
   `resolve_stmt`, before codegen ever runs. Field *access* via a variable
   (`p.x`) is, by contrast, validated only at **runtime**, in
   `code_interpreter.py`'s new `getfield`/`setfield` opcode handlers: since
   there's no static type system yet, there's no reliable way to know what
   struct type an arbitrary expression's value will hold at compile time
   (e.g. a function parameter has no static type annotation at all) --
   this mirrors the same pattern M1 already established for call arity
   (also moved to runtime for the same "callee isn't always statically
   known" reason). `docs/NEXT_PHASES.md`'s future type system is what
   would eventually let field access move back to compile time, as this
   doc's original sketch aspired to.
   **Struct type names live in a flat, unscoped registry**
   (`Resolver.struct_decls: dict[str, list[str]]`), separate from
   `self.scopes`/frame levels entirely -- a struct type isn't a first-class
   value yet (can't be passed around), so it doesn't need real lexical
   scoping: once declared, a struct name is visible program-wide regardless
   of the lexical nesting depth of the `struct` statement itself, and a
   struct type name and a variable of the same name coexist without
   conflict (different namespaces).
   New tokens: `STRUCT` (keyword), `DOT` (`.`), `COLON` (`:`). New AST
   nodes: `StructDecl(name, fields: list[str])`, `StructLit(type_name,
   fields: list[tuple[str, expr]])` (an ordered list, not a dict, so a
   literal's own duplicate field can be detected instead of silently
   dropped), `FieldAccess(obj, field)`. Changed: `AssignStmt.target` is now
   an AST expression node (`Ident` or `FieldAccess`) instead of a bare
   name string, and `AssignStmt.target_address` is removed entirely -- an
   `Ident` target reuses its own resolver-set `.address`, and a
   `FieldAccess` target's codegen (`Codegen._gen_store`) reads
   `target.obj`/`target.field` directly to emit a `setfield`. New opcodes:
   `struct` (`arg1`=type name, `arg2`=tuple of `(field_name, value_addr)`
   pairs, `dest`=new `StructInstance`), `getfield` (`arg1`=struct address,
   `arg2`=field name, `dest`=read value), `setfield` (`arg1`=struct
   address, `arg2`=field name, and the 4th slot -- `dest` for every other
   opcode -- repurposed to hold the address of the value being stored,
   since there's no actual destination: the mutation happens in place on
   the heap object).
   New: `tests/test_structs.py` (19 tests) covering: basic
   declaration/literal/field-read; field mutation visible through an
   alias (reference semantics); nested struct literals + chained field
   access; structs interoperating with M1 closures/functions (passed in,
   returned, computed from other structs' fields); nested (2-level) field
   assignment; field access binding tighter than unary `-`/`**`; `print`
   on a whole struct (`Point { x: 1, y: 2 }`); the if/while
   struct-literal-ambiguity restriction (bare literal in an `if` condition
   raises; parenthesized works); struct-literal validation errors (missing
   field, extra field, duplicate field in the literal, duplicate field in
   the declaration, redeclaring a struct name, undeclared struct type); and
   runtime field-access errors (unknown field read, field access on a
   non-struct value, field assignment to an unknown field) -- all raised as
   clean exceptions via `mah.py run`, never a bare Python traceback. All
   pre-existing M0/M1 tests (46) stayed green, unmodified. New example:
   `examples/structs.mh`.
   Changed: `compiler/lexer.py` (new tokens), `compiler/ast_nodes.py` (new
   nodes, `AssignStmt.target` type change), `compiler/parser.py`
   (`_parse_condition_expr`/`_struct_literal_allowed`, `_parse_postfix_from`
   applied to every primary, `_parse_struct_decl`/`_parse_struct_lit`/
   `_parse_field_list`, `parse_stmt`'s `ID` branch gains a `.`-chain
   field-assignment case), `compiler/resolve.py` (`struct_decls` registry,
   `StructDecl`/`StructLit`/`FieldAccess` handling, `AssignStmt` now just
   resolves `stmt.target` through the same `Ident`/`FieldAccess` dispatch),
   `compiler/codegen.py` (`StructLit`/`FieldAccess` in `gen_expr`,
   `_gen_store` helper, `StructDecl` emits no code), `runtime_values.py`
   (new `StructInstance`), `code_interpreter.py` (new opcode handlers,
   `_to_str` renders a `StructInstance` as `TypeName { field: value, ... }`).
   `preprocessor.py` was **not** touched -- its own tolerant scanner already
   consumes/rewrites module-namespace dots (e.g. `math.square`) before the
   real lexer ever runs, so only genuine struct-field dots reach
   `compiler/lexer.py`.
4. **M3 — enums.** Declaration (unit + struct variants), construction.
   Register the builtin `Option` type (`none`/`some(x)`) here too, as part
   of bringing up the `EnumInstance` machinery — it's not user-declared,
   but it's the same representation and this is the natural point to seed
   it (see "Built-in `some`/`none`" above).
5. **M4 — pattern matching.** `match` over number/string/bool/struct/enum
   (including the builtin `some`/`none`), bindings, wildcard. Guards
   deferred — see `docs/NEXT_PHASES.md`.
6. **M5 — expression-blocks.** `if`/`match`/bare blocks as values
   everywhere (destination-slot threading described above). This is where
   "no tail expression / semicolon-terminated block" starts producing
   `none` instead of a placeholder zero — see "Built-in `some`/`none`" and
   "Blocks/if/match as expressions" above.
7. **M6 — forgiving parse errors** in the LSP diagnostics path.
8. **M7 — LSP rename** (+ retire the independent token-scope model).
9. **M8 — tooling sync.** `syntax-highlight/grammar.js` +
   `highlights.scm` updated for the new syntax; `mah.py build`'s IR dump
   and any new opcodes.
10. **M9 — `defer`.** Block-scoped `defer`, per "`defer`" above. Only
    depends on M0 (blocks, `return`/`break`/`continue`) and M1 (closures,
    for the "compile a defer body as a zero-arg closure" codegen
    approach) — listed last for documentation tidiness, but could be
    scheduled as early as right after M1 if that's more convenient.

Each milestone should land with its own `examples/*.mh` additions, keep
prior milestones' examples running, **and add automated tests covering
it** (`make test` must stay green) — see `docs/TESTING.md` for where
tests live and what's expected; an example file alone doesn't get
checked by anything and won't catch a regression. See
`docs/DEVELOPMENT_WORKFLOW.md` for how to split a milestone's design vs.
implementation vs. verification across model tiers when delegating —
M1 was built and documented that way.

## Status

M0, M1, and M2 are landed (see their entries above for what changed and
each milestone's deliberate deviations/simplifications). `docs/NEXT_PHASES.md`
captures what's deliberately deferred (match guards, arrays/lists,
generics, traits, the type system, async) and what M0–M9 need to keep
forward-compatible with. Next up: **M3 — enums.**
